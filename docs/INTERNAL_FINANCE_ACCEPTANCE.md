# 内部资金流程验收清单

当前阶段不接支付网关，不自动收退款。下列案例先在本地自动测试、再在 Preview 使用明确标注的虚构企业和资金记录验收；不得把测试款项当作真实收付款。托管环境的实际操作结果须另行记录，不能以本地通过替代。

| 案例 | 必须核对的结果 |
| --- | --- |
| 线下收款、独立核实、发布账单 | 收款只记一次；账单扣费只记一次；余额与逐笔流水一致 |
| 客户部分退款 | 申请金额＝实退＋手续费；提交即占用；付款核实后仅追加一次支出 |
| 同时申请退款与发布账单 | 同一笔余额不能重复使用；不足时拒绝后续扣款 |
| 重复提交或连接中断 | 查原申请及流水；相同请求不产生第二笔操作，未知结果不显示为成功 |
| 退款取消、退回或改金额 | 只在允许阶段办理；释放占用；新申请保留新手续费快照，旧记录不覆盖 |
| 付款登记被退回 | 不等于银行没付款；先查原流水，不能直接再次付款 |
| 代理佣金结算前发生退款 | 相关正佣金暂停结算，其他客户不受无关影响 |
| 已结算佣金需要更正 | 保留已付款历史，独立制单及复核调整，不能修改原付款 |
| 越权或本人复核 | 其他企业、其他代理及不具备职责者拒绝；本人不能复核本人制单或付款登记 |
| 人工对账发现差异 | 记录差异依据，先查交易关联，不能直接改余额或删除历史 |

当前自动覆盖参见 `tests/partner-finance-database.test.ts`、`tests/partner-finance-api.test.ts`、`tests/refund-checks.test.ts` 和相关权限测试。以上清单还包含收款及账单等跨模块验收，不能据此声称全部托管案例已完成。

## 本轮补强

内部退款页面增加基于本页记录的待办与核对：展示下一责任环节，检查金额关系、重复有效付款、缺失付款登记、申请与付款状态不对应，以及退回登记后的重复付款风险。检查只读，不改账、不审批、不发送转账。达到列表上限时提示检查范围不完整；没有发现异常不代表银行已到账。客户页面不展示内部核对清单。

未登记手续费约定时，客户仍能看到不可提交的申请入口及原因，不能绕过约定直接提交。
