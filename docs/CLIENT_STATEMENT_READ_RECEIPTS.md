# 客户账单查阅确认

已有 001–030 的项目，在 SQL Editor 新建「27 客户账单查阅确认」，执行 `supabase/migrations/031_client_statement_read_receipts.sql`。只新增空的查阅记录表及受控查询/确认函数，不修改收费、发布、钱包或采购核销规则。现有项目不要运行完整 bootstrap。

客户在 `/zh/account/statements` 查看已发布账单后，主动勾选“我已查看本账单的金额、月份及使用情况”，再点击“确认已阅本账单”。打开页面或下载文件本身不创建查阅确认。确认只记录客户的声明，不表示接受新报价、付款指令或放弃费用疑问，不会再次扣款，也不阻止未确认账单的正常发布及查阅。

只有当前具有企业成员及财务访问权限的客户可确认该企业的已发布账单。内部员工不能代替客户确认；请求忽略浏览器提供的身份、时间或金额，记录身份来自会话，时间来自数据库。每个客户用户/账单只有一条不可改写确认，重复操作返回原时间；新账单 ID 需分别确认。元数据不存储报告内容或文件。

客户只读取自己的确认状态。即使同公司的另一成员也获财务权限，不能通过该查询取得他人的确认记录。内部管理员及获授权财务人员只能从按企业、月份的汇总接口取得确认数量和最后时间，不获得客户用户 ID、电话或私有财务参数。员工汇总需要原有 MFA 和企业范围权限。

撤销客户访问权限后，该用户不能继续确认或查询该企业的查阅记录；历史确认仍作为原账单的审计历史保留。用户已经下载的账单文件不受本操作修改。

月结工作台第四项改为“客户查看与查阅确认”。授权存在不等于已确认查阅；未收到确认也不表示客户从未看过。查询失败或限量不全显示未确认，不能当作已阅。至少一名获授权客户已为每份相应账单确认后，该项才显示条件具备。

未执行031或确认服务暂不可用时，客户仍可查看和下载已有账单，确认按钮暂不可用。保存最多等待30秒，异常提示结果未知并允许安全重试，不自动代客户确认。新记录不对外发消息，不更改财务数据。

验证：贯穿式隔离数据库测试覆盖客户授权前拒绝、授权后确认、重复确认与审计只记一次、跨企业拒绝、员工代确认拒绝、个人记录隔离、撤权后不可读取/确认及历史保留。接口验证同源、登录及显式确认，前端测试无自动提交、正确回执才显示成功及超时可重试；最终客户钱包仍只有原入账和两条费用扣款。
