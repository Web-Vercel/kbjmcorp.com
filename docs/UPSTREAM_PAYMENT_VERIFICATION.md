# 公司间 CAD 到账核对与核销

入口 `/zh/operations/upstream-payments`，位于三方运营中心及已发布月结记录。已有 001–028 的项目，在 Supabase SQL Editor 新建「25 公司间到账核对与核销」，执行 `supabase/migrations/029_upstream_payment_verification.sql`。迁移只创建空的凭证登记、分配和复核表及受控函数，不填入银行交易、发布账单或改动客户余额。现有项目不要执行完整 bootstrap。

## 本轮流程

1. 中国运营公司在线下完成汇款，加拿大 KBJM 实际收到 CAD。保管真实原件并核对双方主体。系统不执行汇款，也不能凭中国汇出金额推算加拿大净到账。
2. 具有 `finance.prepare` 的人员（管理员亦可）选择客户企业、采购账单月份，登记逐笔银行交易参考号、加拿大实际到账日期、净 CAD、原件归档参考、SHA-256、核对说明，以及已发布采购账单分配。
3. 一笔可分配至同一企业的多张账单，最多 20 项；一张账单可对应多笔部分付款。分配必须为不同已发布账单的正数，合计等于本笔净到账。当前页面选择同一月份的账单，接口亦可登记同一企业跨月分配。跨企业合并、无法全部分配的溢付/预付款、退款和冲正不在此流程内，不应以虚构净到账或负数记录代替。
4. 另一位具有 `finance.review` 的人员独立核对原件、付款方、收款方、逐笔银行参考、实际净 CAD 与分配。制单本人不可复核，管理员也不能自审。待复核记录既不计入已核销，也不预留采购额。
5. 复核通过时按确定顺序锁定所有目标账单，重新计算其他已通过记录；任一分配超出尚未核销采购额则整笔不通过。不会发生部分批次先行生效。通过后显示部分核销或核销完毕；“尚未核销”仅代表本系统尚无足够的已复核记录，不证明银行未付款。
6. 退回记录保留，不删除修改。同一参考号只能有一个待复核或已通过版本；被退回后可登记同企业修正版并增加版本号。已通过版本不能更改；更正已通过的错误核销需要后续独立冲正流程，不能重复登记或删除原件。

## 权限与隐私

制单、复核和查看均受 MFA、当前员工状态、运营单位职责及客户企业关联控制。客户、投放员工和未获该企业权限人员无访问权。此页仅投影 CAD 采购总额、已复核/待复核分配、原件参考与核对记录，不输出 CNY 采购换算、汇率、完整报价或原始 API 响应。管理员原采购对账页仍单独保留；其 CSV 不自动汇总核销状态，应查看本流程原记录。

SHA-256 在本机计算，也可登记既有指纹；文件内容不上载。指纹仅比较文件一致性，不证明真实到账，独立复核仍需查看受控原件。银行流水参考统一大写，跨版本及企业避免重复登记；银行真实性与服务商别名不能由文本唯一性自动验证。

## 不可变与幂等

记录、分配、复核结果不可改写；认证用户无表级直接写权限。登记使用固定请求 UUID，原内容重试返回原记录；改动内容会冲突。网络等待 30 秒后提示结果未知，保留原内容重试沿用同一编号。银行参考号事务锁拦截并发重复，账单行锁防止并发审批超额。分配总和及企业一致性由延迟约束触发器在事务提交时校验。核对事件写审计日志，所有操作均不写 `wallet_entries`、不修改正式账单，也不执行真实银行动作。

每月最多显示 200 张已发布账单、100 条相关到账记录（待复核优先）；超限明确提示，不把列表当作完整历史。查询失败显示未知，不显示为已核销或零金额。

验证覆盖 PostgreSQL 实际登记/复核/修订、幂等、重复参考、批量原子性、超额、权限及 MFA、自审禁止、跨企业拒绝、不可变与钱包记录不变；接口字段白名单/精确金额/同源保护、页面状态及客户端未知结果重试。仅使用隔离的虚构测试数据。
