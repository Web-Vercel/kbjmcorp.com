# 本月待发布草稿合计资金核算

沿用001–036，不新增SQL、审批或资金预留。位置在月结工作台“人民币资金状态”内，内部月结办理清单CSV也记录相同核算结果。

## 解决的问题

同一企业多个广告账户共用人民币预付账户。余额CNY600，两份已复核草稿各CNY400时，单份都能被当前余额覆盖，但合计CNY800仍缺CNY200。原单账户阶段继续表示单份条件；新增合计核算提醒整批资金缺口。主流程第一项不再仅因余额大于零而显示资金条件具备。

## 核算口径

仅选当前企业、结算月份内，工作台当前版本中阶段为publication_ready、funding_needed或wallet_needed的草稿。还须有真实草稿编号、approved独立复核状态、来源ready以及有效CNY草稿金额。每个账户只取工作台选定的当前草稿，不累计同一账户的不同版本。

合计以BigInt分为单位计算：当前已入账余额减上述草稿合计。差额为负时，显示正数的资金缺口；恰好相等时为可覆盖。待复核/未登记的银行付款不加入余额、不抵消缺口，已发布账单也不再次计入待发布合计。核算不会插入或改写任何资金流水。

其他未发布账户（尚未制单、来源不满足、未复核、退回、归档、访问暂停等）单独计数并排除。因此可覆盖这些草稿不代表本月所有费用可覆盖，其他月份也共享同一余额。主流程第一项只有本月其余账户已发布、当前待发布草稿可覆盖时显示条件具备；仍有未纳入的未发布账户时保留待处理。所有本月账单已经发布时，仍保留原来的已记账说明。

没有人民币账户时不把余额或缺口推断为零，显示先开户。没有符合条件的草稿时显示尚无本次可核算的草稿，不把未来费用推断为零。输入金额、草稿/账单关系、复核状态、范围或重复编号不一致时显示核算暂不可用。超过1000个账户也不制作部分合计。

## 办理入口与原发布保护

有缺口时可从原入口核对真实银行到账；收款页被指定虚构企业测试模式限制时不提供跨企业收款链接。未开户只有管理员获得CRM开户链接，财务提示联系管理员；可覆盖时链接原结算页。不会自动汇款、审批、预留、修改发布顺序或代客户同意收费。

原发布数据库函数仍先锁定钱包、重新计算已入账余额，再对单份账单验证及扣款。工作台计算是查询时点提示，不能替代每次正式发布检查。先发布一份或其他月份发生扣款后，应刷新核对新的余额与剩余草稿。

## 验证

纯函数/页面测试覆盖600与两份400的200缺口、待核对资金不计入、已发布/未复核/退回/归档不重复计入、同余额覆盖的精度与零费用、负余额、未开户、未知或矛盾资料、同账户/草稿重复、所选企业/月及测试收款入口限制。

隔离PGlite真实SQL流程补充案例：原虚构钱包余额CNY393，两份独立复核草稿各CNY250，单份阶段都为可发布，合计缺口CNY107。发布一份后余额CNY143，剩余草稿CNY250，缺口仍CNY107；第二份发布被原数据库余额检查拒绝，没有新增失败扣款。所有资料均为虚构，没有操作真实银行或预览客户数据。

真实Preview验收无需SQL。部署后刷新工作台，选择有多个已复核草稿的企业/月，对照合计与余额；有缺口时仅登记实际已发生的到账，不为完成状态制造虚构款项。
