# Preview 职责恢复验收问题

用户线上验收：管理员撤销中国财务制单职责后，制单员原会话刷新退款页返回404。恢复操作并重新登录、完成MFA后，同一账号显示加拿大KBJM／加拿大投放执行，财务菜单不可见。此结果不记为恢复通过。

原因：原职责表单与已保存职责选择器互相独立，单位默认kbjm_ca、职责默认ad_operations；AdminForm保存成功form.reset()又恢复这些默认值。只重新选择“启用”会提交默认的另一项职责，而不是恢复原职责。数据库按单位和职责保存记录，菜单按实际授权显示；不应通过扩大菜单权限修复。

修复：从所选人员的已有职责（包含已撤销记录）明确选择调整目标，单位和职责作为不可编辑的关联值提交。新增职责是独立明确选择，单位由职责确定，无默认授权。切换人员清空目标；变更状态重新勾选授权确认。职责表单保存后不执行原生reset，保留目标，其余AdminForm保持原行为。原服务端管理员/MFA及SQL权限校验不变。

本地验证：撤销后保存目标不漂移，再次启用仍提交zhidian_cn/finance_preparer；撤销记录可选择恢复，切换人员清空旧目标。相关3文件15项测试、类型检查通过，完整构建通过。没有运行线上修复或更改权限数据。

线上恢复步骤（仅Preview）：管理员选择该制单员，明确选择加拿大投放执行，撤销保存；再明确选择中国财务制单，启用保存。核查已保存职责：前者已撤销，后者启用。制单员重新登录及MFA后核对身份、运营单位、财务菜单及退款页面。未验证恢复结果前，本项保持未完成。无需新SQL。
