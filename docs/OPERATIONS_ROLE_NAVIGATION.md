# 运营菜单与制单职责核查

2026-11-15，Preview。此前运营首页菜单按职责筛选，右上角 BusinessNavigation 却枚举全体运营路径。页面有权限限制，但菜单仍显示不适用入口。本次仅将已验证的 OpsContext 从服务端布局传入主菜单，按现有页面能力筛选；不增加业务权限，不改 SQL。

## 中国财务制单账号

| 入口 | 应显示 | 职责边界 |
|---|---|---|
| 月结工作台、月度结算制单与复核 | 是 | 核对来源、准备月结草稿；不可独立复核、批准或发布正式账单 |
| 广告来源资料、整月活动覆盖核实 | 是 | 查看获授权来源、提交核实依据；复核由另一有权限账号完成 |
| 报价查看 | 是 | 查看已授权报价结果；编辑、归档、汇率与内部成本仍仅管理员 |
| 对公收款与入账 | 是 | 登记到账依据，提交独立核实；原收款测试范围限制继续生效 |
| 客户资金对账、入账资金摘要 | 是 | 只读核对余额和流水，不直接编辑余额 |
| 公司间到账核对 | 是 | 登记已在线下发生的到账与分配；不可自行独立复核，不发起汇款 |
| 代理业务 | 是 | 准备佣金、扣减及结算、登记已批准的线下付款；代理账号及归属管理仅管理员 |
| 客户余额退款 | 是 | 核算、退回资料不足申请、登记已批准的线下付款；复核和批准分别授权 |
| 服务工单、账单问题跟进 | 是 | 按现有可读企业与类别跟进；回复不自动改变余额或收费 |
| 手工报表交接、手工核对草稿 | 是 | 查看手工来源/草稿、按已有权限退回来源；不因财务角色获得加拿大来源提交权；旧手工草稿生成功能仍管理员专用 |
| 手工关联广告账户 | 否 | 管理员或加拿大投放执行职责 |
| 人员职责 | 否 | 管理员 |
| 广告数据同步 | 否 | 管理员读取 API 和配置归属 |
| 公司间采购对账 | 否 | 管理员查看采购、内部成本构成 |

## 其他角色

复核角色与制单角色可进入同一批财务工作区，但页面内操作分别由 canPrepare/canReview 及独立复核规则约束。管理员保留全部运营入口；加拿大投放执行仅来源相关入口；客服仅服务入口。未能取得运营权限时，仅保留工作台根入口，不猜测或默认显示全部菜单。直接访问隐藏路径仍由原服务端页面/API/RPC 检查，隐藏菜单不是授权机制。

验证覆盖角色主菜单、管理员保留入口、未验证权限、加拿大来源/中国客服区别，以及报价只读、采购页面限制、广告同步限制、制单直访人员职责和关联账户的拒绝行为。

## 复核角色专项检查

独立复核账号保留财务读取入口，菜单与代理子菜单采用“月度结算复核、收款到账复核、代理佣金与结算复核、客户退款复核、整月活动覆盖复核、手工草稿复核、公司间到账复核”等职责名称。工作台说明同步调整，不提示复核人员准备草稿或发布。报价保持只读。

专项验证：复核人员无新增收款/收款配置表单，无佣金核算表单、代理账号管理或合作文件管理入口；可以复核他人佣金，自己的佣金记录不出现复核控件；已复核账单也不显示正式发布按钮；公司间到账可以复核但不显示登记表单。数据库测试直接验证复核账号不能核算退款、批准退款、生成佣金、制作代理结算单、批准代理结算及登记付款；仍可执行独立复核。页面、API 和数据库原权限不因菜单改名而放宽。

## 逐路径职责复核（剩余15项）

核查不仅看能否访问，还检查该入口为何参与当前角色的财务闭环；右上角菜单与工作台入口共享筛选策略，角色内按钮和数据库权限继续独立检查。

| 路径（operations/ 后） | 制单角色用途 | 复核角色用途 |
|---|---|---|
| agents | 核对计佣归属依据，核算佣金与扣减、准备结算、登记获批准付款 | 独立复核佣金、扣减、结算及付款；不管理代理账号或客户归属 |
| refunds | 核算客户申请、要求补正、登记获批准的线下退款 | 独立复核退款核算与付款；不最终批准退款 |
| manual-sources | 核对人工来源、发现依据不足时按现有权限退回补正；不提交加拿大报表 | 查阅手工原件依据，核对问题并退回来源补正；不提交加拿大报表 |
| manual-finance | 查看管理员所制旧流程手工草稿与复核进度，不新增该类草稿 | 对他人提交的手工草稿独立复核 |
| fund-summary | 查看入账/占用/可用资金及月度资金摘要，作为制单依据 | 查阅入账和资金状态，作为独立复核依据 |
| service-requests | 财务咨询工单：仅数据库允许的 billing 类咨询，可包括尚未绑定正式账单的问题 | 同样仅处理有权限的账务咨询；一般账户、报告和其他客服类别不因财务角色开放 |
| month-close | 查看各企业月结阶段，找到来源、报价、资金或制单缺口 | 定位待独立复核及等待前序流程的事项 |
| source-data | 查看已交接的广告来源与统计范围，作为制单输入 | 独立核对原始来源、客户归属和统计期间 |
| source-checks | 提交完整月活动核实依据 | 独立复核他人提交的整月覆盖依据 |
| pricing | 读取已授权报价结果作为收费依据，不修改报价 | 读取报价结果核对草稿金额，不修改报价 |
| settlements | 月度结算制单与被退回后的后续处理 | 独立复核他人月度草稿；无正式发布权 |
| collections | 登记已有实际到账依据，交另一人检查 | 独立核对他人登记的到账，按原入账流程确认或退回 |
| funds | 逐笔资金流水及月度期初/入账/支出/期末核对 | 用同一只读账本独立核对资金变动，不直接编辑余额 |
| upstream-payments | 登记公司间实际到账及采购账单分配 | 独立核实净到账与分配；不是发起汇款 |
| statement-questions | 按企业、月份定位已关联正式账单的问题并处理 | 跟进账单核实问题；回复不代表审批、改账或再次扣款 |

上述“服务工单”在纯财务角色下改名为“财务咨询工单”；它与“账单问题跟进”不是不同权限，后者是正式账单及月份的专项视图，而前者覆盖未绑定正式账单的账务咨询。菜单不将一般客服职责交给财务。制单侧的“代理业务”“手工报表交接”“手工核对草稿”分别明确为代理佣金与结算、手工来源核对、手工草稿进度，归属页签明确为客户归属依据。

## 管理员名称一致性检查

管理员覆盖代理账号、客户归属与引荐、合作文件及佣金/结算管理，因此模块名称统一为“代理与佣金管理”。制单和复核分别保留财务职责名称；管理员不缩减为单一佣金核算角色。代理页面标题和子菜单共享同一角色命名表：管理员使用客户归属与引荐、佣金核算与复核、月度结算管理、合作文件、代理账号管理；制单使用客户归属依据、佣金核算、结算制单；复核使用客户归属依据、佣金复核、结算复核。外部代理自己的菜单保持不变。

同一角色的主菜单、面包屑及首页入口还统一了月度结算管理、对公收款与入账、手工报表交接、整月活动覆盖核实、手工关联广告账户等名称。非管理员即使同时拥有制单和复核职责，名称仍只体现财务工作，不暗示代理账号管理或最终批准权。此次纯命名一致性调整，无 SQL、无角色授权或账务变化。
