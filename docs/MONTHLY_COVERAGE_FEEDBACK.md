# 整月活动覆盖依据与复核回执

沿用001–037，无新增SQL或审批。核实依据登记及独立复核改用专用表单，不改变完整自然月、CAD、花费/展示/点击一致、零活动/未启用分类、原件指纹及另一账号复核要求。

登记API必须收到有效核实UUID后才确认，返回核实ID、来源快照ID及submitted操作回执。重复请求可能返回已经复核的原依据，因此不把这份回执宣称为“当前待复核”，也不直接称已通过；界面要求查看原记录当前状态。原SQL请求编号和内容一致保护保持。测试增加已通过复核后原样提交仍取得同一ID的断言。

复核回执必须与本次原核实ID及所选通过/退回决定匹配。通过不宣称一定可制单：最新来源、其他核实版本、交接访问和报价条件仍以工作台重新核对为准。退回指向原记录说明。两种操作均不发布账单、扣款或改写原始广告数据。

表单并发点击锁及30秒上限防止无限等待。未知结果保留原依据、指纹、说明、确认及请求，不自动重试或清空内容；核查链接新标签打开，保留原页面。原样重试沿用同一请求；改动内容可能被原SQL拒绝，不能覆盖已冻结依据。原活动分类切换时重新填写确认/依据的既有行为保持。

来源页原快照锚点及核实记录新锚点提供精确定位。回执/核查链接保留企业和结算月份，后续可回对应月结工作台。结果列表为加载时状态，打开原记录读取最新结果；链接不授予权限。原页面不向制单者提供自审，不为已处理记录再次显示复核表单；读取失败不显示操作按钮。

验证：统一财务闭环27文件207项通过，包括API、登记/复核表单、页面权限及原monthly-settlement数据库规则。8项本地Chromium用例覆盖登记/复核×中英文×手机/桌面，使用真实证据组件及虚构接口响应，保留手动登记的虚构指纹与说明、验证同请求重试和记录链接。没有真实广告读取、文件上传或财务写入。类型检查与Next构建通过；不等于线上部署已核实。
