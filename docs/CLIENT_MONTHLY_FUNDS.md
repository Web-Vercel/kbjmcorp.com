# 29 客户月度资金对账单

在032之后执行 `supabase/migrations/033_client_monthly_funds.sql`。这是只读查询迁移，不改写流水、不产生扣款、不自动认定客户已阅。已有项目不要重跑空库初始化脚本。

## 用途与入口

客户中心“充值与使用明细”下进入“查看 / 下载月度资金对账单”，路径 `/zh/account/funds`（英文 `/en/account/funds`）。按已授权资金账户和已结束自然月查询，默认上个已结束月份。

按 **America/Vancouver 实际入账日期** 划分月份，起始当地零点包含、次月零点排除，夏令时自动处理。它与广告账户的统计时区、广告结算月份是不同口径；例如十月份广告账单十一月才发布扣款，这笔支出进入十一月份资金对账单。不能直接用某月资金支出与同月广告报告总额相等作核对。

期初余额 + 全部当月正向入账 − 全部当月负向支出 = 期末余额。包含所有已入账类型（含正负对账调整），不包含待核对付款、未发布草稿或尚未入账广告费。没有流水时余额结转，不据此断言广告使用为零。不同币种分别查询，不换汇；期末余额不是当前余额。

## 访问与数据边界

RPC `get_client_monthly_funds(uuid,date)` 必须具有该企业个人成员和财务授权，内部员工/管理员没有额外绕过权限。显式投影公开资金字段，绝不输出银行原件、source_reference、内部报价、上游CAD成本或汇率。关联账单只从同一钱包正式账单匹配，客户仍受账单查询权限保护。

汇总始终基于全部已入账记录。在单次一致数据库快照内计算，不从首页最近100条推算。月度明细最多读取1000条；页面表格最多100条；未超过1000条时CSV包含本月全部明细。超过1000条明确提示、保留完整汇总、停止CSV导出，联系财务取得完整明细，不把截断文件称为完整对账单。

这是查询时点快照，显示生成时间，不是新付款要求、银行实时余额或税务发票。后来入账会影响后来查询；导出的文件不会自动更新。调用失败/校验不通过显示不可用，不显示虚假零余额。查询和下载不写数据库。

## 验证

- PGlite真实SQL测试：跨企业未授权拒绝、非月初及未来月份拒绝、夏令时月底边界、正向调整与负向费用、零流水结转、不同币种不混算、超过1000条完整汇总和导出阻止。
- TypeScript：超过JS安全整数的金额保持BigInt精度、汇总与明细相符校验、CSV公式注入保护、额外私密字段剥离。
- 页面测试：只查询授权钱包、不可用时无导出/虚假零额、无流水仍可正常对账。
- 主流程贯穿测试加载001–033，原客户扣款、余额与公司间核销行为不变。

真实客户验收：033执行且Preview部署完成后，由具有个人财务授权的客户登录。选实际有入账记录的月份，核对期初/入账/支出/期末与CSV；如广告账单扣款在下月入账，请查实际入账月。没有记录时无需创建虚构真实到账以填充页面。
