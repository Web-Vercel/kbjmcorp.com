# 客户资金对账页登录后返回

沿用001–037，无新增SQL或审批。客户打开 `/zh/account/funds?wallet=...&month=YYYY-MM` 时，未登录会先进入原手机号登录页；通过验证后返回指定资金账户和入账月份。资金页的语言切换也保留选中的账户与月份。

返回目标只增加客户资金对账路由，允许wallet UUID和month月份两个参数；禁止外部网址、员工后台、重复参数、未知参数、无效编号/月、片段及路径绕行。既有账单专用解析函数仍仅接受账单，不扩大到任意客户页面。合作申请流程仍优先。普通手机号验证及隐藏Preview测试账号验证共用同一校验，验证前不跳转、不自动提交或授予权限。

这只是页面导航提示，不保证账号有权查看指定钱包；登录后仍从现有授权钱包RPC取得列表，并核对所选钱包和资金对账数据。资金查询失败仍显示未知，不把余额当零。资金月份仍按原页面限制为已结束月份；不会因返回参数而放宽。

验证：50项单元、页面和登录组件测试，涵盖登录成功前不跳转、验证后保留目标、非法目标回退、资金页会话跳转前不读财务RPC、原账单/工单回归。Next.js构建及TypeScript检查通过。浏览器脚本 `scripts/funds-login-smoke.mjs` 可针对本地已构建页面运行，不发送验证码或财务写入。

本轮浏览器实测完成8项：中英文×375/1440宽度的未登录资金页跳转及语言切换，加4个非法返回目标回退案例；确认没有认证提交或财务API调用。登录完成后的最终导航使用组件中的虚构认证响应验证，不替代真实客户身份验收。
