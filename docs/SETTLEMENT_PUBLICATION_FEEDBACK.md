# 结算页资金衔接与发布结果核查

沿用001–036，无新增SQL、审批或资金预留。入口仍是 `/zh/operations/settlements`，管理员发布、制单人员准备、另一位财务独立复核的权限不变。

## 结算页衔接

新增可留空的月份筛选。选择企业/月时，原四个列表查询与工作台资金概览、账单问题查询并行执行，月份在数据库限制条数前筛选。结算页显示与工作台相同的待发布草稿合计及缺口，并能进入同月账单问题处理。资金和问题提示的查询失败不会伪造零余额，也不隐藏原有有效制单/复核记录。

留空月份保留原来的跨月最近50份记录，不把不同月份汇总成一个资金计划。每份发布表单的返回链接使用该草稿实际月份，而不是推断当前月份。资金合计的“查看待发布草稿”链接定位结算页草稿区。

## 本次发布预览

匹配当前工作台草稿、企业、月份、金额及复核条件后，才提供人民币余额预览：当前已入账余额、本次拟扣、如果只发布这一份的核算后余额。旧版本或资料缺失显示预览不可用；未开户不显示假零余额。

此处仅为查询时点参考，不预留资金、不计入未核对到账。合计不足与单份可覆盖分别显示，管理员仍可按实际安排发布其中一份。其他账单可同时消耗余额；每次实际发布仍由数据库锁定钱包并重新校验，不使用浏览器提交的余额或汇率。

## 发布反馈

正式发布表单专门处理金额写入反馈，沿用原一次勾选确认，不新增审批。提交仅发送草稿编号、客户可见说明及确认；不接受浏览器的企业、月份、金额、汇率或结果身份。API仍在服务器重新验证锁定报价并由原数据库函数完成发布。

表单防止重复点击，等待最多30秒。只有HTTP成功且响应为明确ok=true及有效UUID账单编号时显示成功，并刷新原页面；API也校验返回编号格式。格式不明、服务错误或超时只提示结果未知/未确认，保留原说明和确认，不声称没有扣款。

用户可点击“刷新核查发布与余额”，仅刷新页面，不再提交写入。看到原回执后以回执为准。网络结果未知时显式重试原草稿、原说明沿用数据库既有幂等保护；同一草稿不会重复扣款。修改说明不能改写原发布账单，数据库会返回冲突。表单不自动重试。

明确余额不足错误提示本次未发布/未扣款；同账户月份已发布、记录冲突、权限/二次验证等错误分别提示核查。公布编号后原表单不再提供重复提交；原列表仍以不可改写回执代替发布入口。

## 验证

组件测试验证预览不写入、防连点、只有有效回执才显示成功、HTTP200但缺回执时不报成功、30秒超时保留原参数、资金不足保留说明、手动刷新不重复提交。API测试保留同源/MFA/管理员、服务器重算、余额不足和重复月份保护，新增不合法回执不得作为成功。

页面测试验证同企业/月的资金缺口和逐笔预览、附加提示不可用时不显示假零余额、跨月浏览兼容及月份链接保留。隔离PGlite案例仍验证重复发布不重复扣款，并验证余额393、拟扣250的预览143；发布一份后，另一份预览为-107且原数据库拒绝资金不足的发布。全部为虚构资料，没有操作真实银行或广告账户。

Preview部署后直接刷新结算页即可，无需SQL。真实发布仍需真实来源、收费约定、独立复核和真实已入账资金，不为验收按钮而创建虚构真实扣款。
