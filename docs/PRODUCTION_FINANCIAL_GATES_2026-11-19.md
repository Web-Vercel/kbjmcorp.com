## 可直接复用的核对工具

- `npm run verify:financial-gates`：只在新建的、`--network none`、无端口映射的临时PostgreSQL容器内写入虚构fixture；观察真实锁等待和重复请求结果；原生加密备份与独立数据库恢复；结束清理自己的容器及卷。需要本机Docker和postgres:17镜像，不连接Supabase。
- `npm run verify:isolated-recovery`：本地PGlite隔离全量恢复，验证最新53迁移、不可改流水和A/B范围；包含备份后缺口核对。
- `npm run check:production-boundaries`：应在安全注入的Production配置上下文执行，只输出布尔状态。检查Production环境、独立项目URL、public/server密钥形状和分离、限流密钥、验证码配置存在、Preview测试/演示/验收目标未启用、当前暂缓的SMS/自助申请未开启。**它不验证变量在Vercel的作用域、密钥真实对应项目、验证码配对或备份，不能单独放行上线。** 不导出或发聊天中的密钥。
- `supabase/verification/production_financial_preflight.sql`：只有`BEGIN READ ONLY`、元数据/聚合SELECT、`ROLLBACK`。返回数据库身份、必须函数/表、函数指纹和search_path、金融表RLS/直接写权限、不可改账触发器、Storage桶隐私及验收资料数量。没有业务原文、密码、MFA秘密或签名文件链接。已在隔离最新数据库验证；**尚未在托管Production执行**。
