# 客户后台重新聚焦：充值与中文月报

## 产品主线

客户主要查看资金和每月广告使用情况。`/account` 与 `/client-preview` 首页调整为：
1. 已核对的代理预付资金余额、累计充值到账、最近结算月平台广告费用、该月代理服务费。
2. 充值入口：登记已有付款的核对申请，待实际到账核实后才可入账。当前不执行支付、收款或扣款。
3. 每月报告：按月份查看中文阅读版，切换中英说明，通过浏览器打印或保存 A4 PDF。
4. 最近收支与充值核对记录；余额提醒与业务联系说明。

项目、需求、创意协作保留在“其他服务”折叠区，不占据客户首页核心位置。内部员工 CRM 保留。

## OpenAI 报告的中文能力：尚未确认

当前没有该广告账户的实际导出样本、报表说明或可用只读 API。尝试访问以下官方页面时，环境代理均返回 Tunnel connection failed: 403 Forbidden，未取得页面内容：
- https://openai.com/advertisers/
- https://ads.openai.com/
- https://help.openai.com/

不能从这次访问失败推断 OpenAI 不支持中文，也不能承诺支持中文报表、CSV、PDF或自动同步。下一步需在实际广告账户的报表/导出界面核实语言和格式，或取得官方说明与一份已脱敏的实际导出样本。

设计兼容两种情况：
- 有官方中文原件：保留原件、记录原件语言，可直接提供官方中文文件；不重复翻译。
- 只有英文原件：保留英文来源，导入并核对金额/币种/期间/时区/实际账户归属，再整理中文字段和说明。翻译后需核对再发布。当前没有接入自动翻译模型、自动文件解析或实际报告导入。

本次 PDF 是本公司客户阅读模板，不是 OpenAI 原生导出的中文报告。演示文件全文标注“全部数据虚构、非 OpenAI 官方报告”。PDF 能力来自浏览器的打印/保存功能，不是后台自动生成与存档服务。已实际生成并验证中文 PDF 可提取文字、金额与来源说明。

## 资金与报告数据边界

- 代理预付余额不等于 OpenAI 广告平台余额。它由全部已入账流水求和；待核对申请不增加余额。
- 广告费用来自经过核实的平台报告；代理服务费单独列示。当前采用人民币结算，默认不收未约定的服务费；税费、真实支付与银行通道仍未接入。
- 金额以整数最小货币单位存储。前端 BigInt 计算和显示，汇总由数据库返回十进制字符串；不使用浮点运算、不跨币种自动合计或换汇。新客户结算币种为 CNY；CAD 保留为平台费用原币。汇率计算与有依据的费用单独列示，见 CNY_SETTLEMENT_POLICY.md。
- 不把“尚未发布”“未配置”“无法读取”当作零花费或零余额。不提供没有数据来源的实时消耗。
- 月报区间以月度及原报表时区为准，显示关联广告账户、原件语言、文件名、核对状态与修订版本。
- 充值申请和余额显示不是在线支付。没有银行账号、二维码、支付 SDK 或付费短信供应商被配置，没有真实款项被收取或入账。

## 迁移 008：隔离的财务架构

`008_client_billing.sql` 仅在 PGlite 测试执行，未部署到托管数据库。

- finance_access：独立财务授权，引用已核实的公司成员。项目协作权限不自动获得财务权限。viewer 可读，manager 可登记充值核对。初次财务授权与钱包开立由受控服务完成，未实现管理员授权界面。
- client_wallets：客户公司及币种独立的资金账户。
- wallet_entries：有唯一来源引用的已入账流水，禁止更新/删除；修正须追加调整。客户不能写入、改余额或确认到账。全部流水参与余额汇总，界面只展示最近记录。
- client_topups：充值核对申请，固定 pending，独立于资金流水。请求校验同源、真实用户、财务权限、金额、参考号及待处理数量；同一钱包参考号不重复。此模块不实现财务人员实际核对/确认入账。
- monthly_ad_reports 与明细：原件元数据、私有存储标识与 SHA-256、实际广告账户归属、币种、月份、修订号、中文说明、费用拆分。仅可读取已发布且获得财务权限的报告。原件私有位置和核对人员 Auth UUID 不授予客户读取。
- 报告发布需来源元数据、核对人、中文原件或已核对中文说明、合法时区、关联本公司广告账户及明细合计一致。已发布报告及明细不可覆盖，修正采用新版本。父报告锁阻止发布与明细修改并发覆盖。上述约束不验证文件真实存在或文件字节哈希；可信导入/发布服务仍必须核实。

**尚未实现的财务运营能力**：支付与退款渠道、银行到账核对、可信记账/调整与月报费用入账服务、报告原件上传/私有下载、实际文件解析与校验、翻译服务、发布操作界面、余额预警通知、对账差异处理。这些未完成前不能作为真实收款与结算系统使用。service_role 权限不能被放进浏览器，不能用手工随意写表替代受控财务操作流程。

## 真实页面与公开演示

- `/{locale}/account`：真实用户会话下的财务首页。未配置或缺少财务权限时显示明确状态，不展示演示余额。
- `/{locale}/account/reports/{id}`：财务 RLS 隔离的月报阅读页，匿名跳转登录，无权限与不存在的报告统一 404。无法读全明细时不显示不完整的最终报告。
- `POST /api/billing/topups`：只创建待核对申请，返回 pending，不能入账。
- `/{locale}/client-preview`：虚构资金与月报示例。充值申请只在当前页面内存中模拟，刷新清空，不发业务写请求。
- `/{locale}/client-preview/reports/demo-2026-10`：中文/英文月报示例及打印。保留演示水印，不能当作真实报表。

报告超过 1000 条明细时页面失败关闭，后续需分页/服务端生成，不能静默截断后输出正式 PDF。月报和交易列表目前最多读取最近 100 条，余额 RPC 则计算全量流水。真实财务留存、权限管理、存储地区与服务联调仍待确认。

## 本轮验证

169 项自动化测试（22 个文件）及 Next.js 生产构建通过；33 项公开路由检查、28 项员工后台检查、14 项客户中心检查、26 项辅助协作检查及 25 项充值/月报/打印检查通过。实际生成两页中文示例 PDF，并用 pdftotext 核对中文标题、演示声明、金额与来源说明。测试涵盖精确金额、财务权限隔离、申请不入账、已入账流水不可覆盖、报告草稿不可见、原件私有位置不可读、发布前明细对账及发布后不可修改。这些测试不代表真实支付、报告导入或托管服务联调通过。
