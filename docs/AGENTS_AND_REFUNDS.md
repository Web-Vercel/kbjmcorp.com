# 代理与客户余额退款 — 第一版

日期：2026-11-14。代码与迁移仅用于 Preview 验证；本轮不发布 Production，不创建真实账号、不配置真实费率、不执行银行转账。

## 页面与角色

- 外部代理：`/zh/agent`、`/clients`、`/commissions`、`/settlements`、`/files`。通过现有 `/zh/access/login` 邮箱和密码登录进入，无需设置验证器，支持多家确认关联客户。
- 中国内部办理：`/zh/operations/agents` 下同名栏目，另有 `/settings`。管理员管理身份、归属及规则；制单员核算、制结算单和登记付款；复核员独立检查；管理员批准安排付款。
- 客户申请：`/zh/account/refunds`，客户主菜单新增“申请退款”。内部办理 `/zh/operations/refunds`。
- 销售保持原角色和权限，没有新增销售功能。代理不是员工、客户或投资人，不能获得旧员工／成员／业务角色授权。代理的 context.organization_id 是代理自身 ID，用于兼容现有登录上下文，不是企业授权；任何企业授权都来自确认的归属记录。旧业务数据接口仍拒绝代理。

## 代理身份与客户归属

已有账号由管理员核实邮箱、Auth 用户编号及协议后建立代理身份；新账号可在代理账号页创建，默认暂停。核实后再启用。创建不会发邮件；初始密码安全交付。暂停／启用会使旧会话失效；代理重新使用邮箱和密码登录。Auth 创建成功但身份配置不明时显示用户编号，禁止盲目重复创建。

客户线索提交不等于归属。管理员先确认线索，再登记客户归属与计佣规则。一个代理可关联多家企业，同一企业的计佣有效区间不能重叠。第一版以完整业务自然月分配计佣归属，日期均为月初、结束月不含在有效期内。真实引荐经过和协议日期记在依据及文件内。归属终止须为未来月份；移交时保留旧记录，再创建不重叠的新期间。比例、基数和等待期不能直接覆盖历史。

## 佣金与月度结算

第一版不是充值即支付全部佣金：只有实际银行收款支持的正式发布业务，才按归属规则核算。数据库要求已复核银行收款扣除已退款总额，足以覆盖截至原账单发布时的累计客户账单。基数由协议明确选“已发布服务费”或“已发布账单总额”，比例精确至基点；按分计算，四舍五入。原始成本、内部汇率、客户余额和银行原件不提供给代理。

- 制单员准备佣金 → 另一人复核 → 在实际办理日满足等待期 → 纳入已结束的北京时间业务自然月结算单（可补结旧月或合并以前月份未结项；办理日已确认的扣减一并抵扣）。
- 结算制单 → 另一人复核 → 管理员批准安排 → 线下付款后登记 → 另一人核实付款。批准不代表已付款；本系统不自动打款。
- 退款进行中：相应客户的正佣金暂停纳入新结算，已有相关结算在付款登记前也会受阻。可先结算其他不受影响项目。
- 佣金扣减单独准备和复核，不能超过原已确认佣金减去已有有效扣减。负数抵扣留在未结净额中，不伪造负数银行付款；无正额则等待后续佣金抵扣。第一版不实现独立向代理追款的银行收款流程。
- 待复核扣减阻止新结算；未纳入结算的扣减阻止原结算继续批准／登记付款。管理员可撤回未付款结算并重新制单，原单和纳入明细保留。
- 已真实付款的核实不能被后来新出现的退款假装成未付款；按银行事实确认原付款，再按协议另建扣减调整，不改已付款历史。
- 未使用预付款的退款不会自动扣已经赚取的佣金；若原计佣业务另有退费／费用更正，由制单员注明依据，独立复核扣减。

佣金、结算 CSV 只含本角色可见的明确字段，做公式注入防护。列表最多 200 条；达到导出上限时拒绝生成可能不完整文件。没有虚构预计金额；尚未出账的预付款显示为等待服务发生后核算。

## 客户退款

目前处理人民币 CNY 资金账户。

1. 管理员先与客户约定手续费，再登记固定人民币金额或退款申请金额百分比（二选一，不叠加）。第一版没有默认费率。新版本不改已有申请。
2. 客户看申请上限、费用约定、手续费和预计实退，确认后提交。申请金额含手续费，净退款必须大于零。
3. 提交原子占用申请总额。上限扣除其他退款占用及有效的已复核未发布月结草稿；尚未出账、未制单等费用仍须财务人工核实，界面明确提示上限并非无条件可退金额。
4. 制单员核实所有未结费用、收款资金可用性、原付款方及退款账户、收费依据。需改申请金额时退回，客户重新按正确金额申请，不静默修改约定。本人不能独立复核。
5. 另一人复核 → 管理员批准安排 → 线下实际退款后登记银行唯一流水、净额、脱敏收款身份、付款日期和原件参考 → 另一人核实。
6. 最后核实通过，在同一事务中解除占用，追加“净退款支出＋手续费支出”，合计扣除申请总额；不重复记账。核实前仍保留占用，付款登记退回不代表银行实际未付款。
7. 客户只能取消尚未核算申请。管理员可撤回尚未付款的已核算申请；一旦有有效付款登记，不允许撤回。所有历史保留。

余额占用由 wallet_entries 的数据库触发器保护，锁定与现有发布／收款相同的钱包行，避免退款和账单花掉同一笔钱。没有退款占用时保留现有记账语义。新功能没有改变原账单计算、收费比例或公司间 CAD 核销；不会拿 CAD 核销撤销代替客户退款。

## 私密文件

私有桶 `partner-documents`，4 MB PDF／PNG／JPG。API 有源校验、已验证角色、请求体上限、二进制格式识别、SHA-256；路径固定为代理 ID／文件 ID／document.扩展名。引荐证明必须关联同代理线索或确认的客户归属。合作协议属于中国智点未来运营公司与代理；上传不等于签署、不确认归属、不产生佣金。

代理只读自己的文件，管理员可读，普通财务、客户、投资人及其他代理不可读。没有对象更新／删除策略，版本追加保留。元数据失败不会宣称存档成功；未登记对象不可读，需管理员核实后通过受控后台清理。文件短期签名 60 秒，不生成公开永久 URL。存储未配置即不可用，不降级公开。代理文件上限 200 个，额满联系管理员归档处理。

## 部署与验收

现有 Preview 数据库已到 040 时，只执行 `supabase/migrations/041_agents_refunds.sql`；不把新项目完整 bootstrap 用在现有数据库。迁移在一个事务内完成，不插入账户、客户归属、费率、手续费或资金记录。私密桶也在同一迁移创建；需核实文件保管与数据库项目选择符合实际安排。

本地 PGlite 验证新旧数据库流程；前端与 API 验证精确金额、权限、同源、MFA、回执、未知结果和私密上传。当前执行环境无托管数据库迁移凭据，因此不能把本地验证说成 Preview 数据库已升级。先应用增量迁移，再用虚构企业、代理和两位财务账号完成托管验收。Production 另行发布，不能复制测试数据。

## 代理登录要求调整（042）

在已应用 041 的 Preview 数据库执行增量迁移 042。仅代理免验证器；其他角色及财务审批仍要求 MFA。已设置的验证器不会被自动解除。邮箱核实、启停、会话失效与数据隔离继续执行。

## 客户登录要求调整（043）

客户与代理均无需设置验证器，使用邮箱和密码登录。客户仅访问自己的企业，可申请或取消本人尚未办理的退款；审批和付款确认仍由具备二次验证的财务人员办理。先执行 042，再执行 043；不自动解除现有验证器。

## 后续在线支付边界

当前保留人工收退款及客户退款申请，不开通在线充值、自动退款或客户直接改余额。后续分三步扩展，详见 [支付与余额管理设计](PAYMENT_EVOLUTION.md)。
