# 三个真实Production账号：开通规范与当前缺口

2026-11-11（温哥华）。本方案按用户最新要求使用真实Supabase Auth用户、真实正式业务页面和持久记录。独立`/demo`会话及DEMO_*变量继续仅用于旧虚构演示，不自动转为正式账号，也不构成Production开通。

## 账号分配

| 显示名 | 正式职责 | 访问范围 | 禁止 |
| --- | --- | --- | --- |
| investor-demo | 投资人只读查看 | 管理员明确指定企业/账户的获准经营资料 | 修改、提交审批、资金处理、成员管理、密钥及平台管理 |
| client-demo | 企业客户 | 核实后指定企业；按成员与财务授权访问 | 其他企业、内部汇率/采购利润、财务审核、员工授权 |
| sales-demo | 中国销售/客户服务 | 明确分配企业的客户资料及销售服务操作 | 全客户默认访问、余额修改、财务复核、报价内部汇率、员工授权 |

三个名称是显示名或账号别名，实际使用Supabase支持的验证身份。须提供对应邮箱及企业范围；不以demo后缀识别权限。普通网页账号不赋予GitHub、Vercel或Supabase项目管理权限。

客户的finance manager可提交到账通知，但不是到账复核权限，更不能直接修改余额。财务制单、独立复核和正式发布继续由原授权人员办理。投资人如需更多经营字段，应先列明可披露范围，不能借用管理员接口。

## 已有基础与必须补齐项

- 现有正式员工认证支持MFA；现有客户企业成员和finance viewer/manager授权有数据库约束。
- 现有独立演示Auth不适用于真实账号，不可把DEMO_ACCOUNTS_JSON当成正式用户注册。
- 现有中国customer_service内部角色是机构范围，并非销售人员的逐企业分配。不能直接给sales-demo该角色后声称它仅访问指定客户。需补齐数据库及接口的企业范围约束，覆盖列表、详情、导出和写入。
- 现有系统没有符合此需求的投资人真实只读角色。需提供最小字段、指定范围的只读查询和页面；不能授予finance_preparer/reviewer/admin冒充只读。
- 正式客户目前以手机号认证为主；已有邮箱验收入口限制Preview及两个用户。Production邮箱密码体验不能通过解除Preview限制草率实现，需独立受控账号允许清单及原企业授权检查。
- 现有应用不提供完整的真实账号创建/暂停管理台。开通、暂停必须通过可信Auth管理连接及管理员控制的业务授权；当前会话无可调用的Supabase账号管理工具，不宣称已创建或暂停。

## 暂停、恢复和结束展示

1. 暂停账号登录、撤销所有刷新会话，并在数据库业务授权层同步暂停访问。
2. 不假设改密码或Supabase Auth ban会立即让所有已签发JWT失效；须验证旧access token的直接数据库/RPC访问也被拒绝。
3. 记录操作人、时间和原因，历史账单、余额、审批和销售记录保留，不通过删除业务记录实现停用。
4. 恢复时重新核实原企业范围和角色，显式恢复，不自动提升权限。
5. 活动结束可更换密码并注销全部会话，或直接暂停；真实资金与广告费用仍按原记录结算，换密码不会清账。

## 开通顺序

提供三位登录邮箱、每位允许的企业/账户及投资人可披露字段 → 准备并审阅权限迁移及页面 → 隔离库执行权限测试 → 在Preview用真实Auth身份联调但不登记虚假真实到账 → 用户安装明确编号的迁移 → 通过可信Supabase Admin连接创建/关联非管理员用户 → 按清单分配授权 → 完成MFA/登录及跨企业拒绝、只读拒绝写入、暂停后旧JWT拒绝验收 → 另行授权Production部署。

当前没有创建Auth用户、修改真实权限、发送邀请、运行托管SQL、写入真实资金或发布Production。账号邮箱与企业范围待用户提供；不得编造邮箱、默认全企业授权或把管理员账号用作这三个角色。
