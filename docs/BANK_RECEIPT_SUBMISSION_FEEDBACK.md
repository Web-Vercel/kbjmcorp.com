# 到账制单与独立复核回执

沿用001–037，无新增SQL或审批。收款配置仍沿用原管理表单，仅替换实际到账登记与独立复核的反馈。

登记成功时，API要求原prepare_bank_receipt返回有效UUID，表单显示到账记录编号及“待另一账号复核，尚未入账”。复核成功时，只有与本次原记录和选择决定相符的回执才会显示“已入账”或“已拒绝”；review_bank_receipt仍是原子入账和同决定重试保护的唯一执行方。没有新增银行转账、余额修改或客户付款动作。

回执链接保留企业和月结月份并定位原到账记录。月份仅用于返回工作台，未筛除其他日期的预付款。成功后刷新原数据，复核回执在刷新后仍保留；重新加载已经处理的记录不会出现复核表单。制单人不能自审，相关角色与员工二次验证仍由原SQL/guard检查。API仅回传最小编号/动作状态，不返回银行原件或账户详情。

两种表单均有点击锁、30秒超时；未知结果保留输入，不误报未保存或未入账，不自动重发。重复银行流水号提示先核查原记录，不改号重登；冲突、过期会话、二次验证或权限不足保留输入并要求核查。再次登记必须显式选择另一笔款项。虚构模式明确标识非实际收款，原服务器限定虚构企业和不可付款收款账户的保护保持。

统一验收使用npm run test:finance-loop，增加到账回执/API/企业筛选/虚构模式用例。另有8项本地Chromium检查：登记/复核×中英文×手机/桌面，验证带企业月份的链接、成功回执和503未知结果保留依据。使用虚构响应，未写入真实客户或银行数据。类型检查与Next构建通过。
