# 30 财务与客户同口径资金对账

在033之后执行 `supabase/migrations/034_ops_monthly_funds.sql`。只读功能，不新增收费或审批，不迁移、重写或修订已有资金流水。已有项目不要重跑空库初始化脚本。

## 办理场景

客户问某月预付款还剩多少、某笔费用为何在下月扣款时，中国财务可直接在 `/zh/operations/funds` 查询企业的人民币资金账户，不用客户账号。三方运营中心及月结工作台“人民币资金状态”提供入口。英文同路径 `/en/operations/funds`。

与客户 `/account/funds` 共用数据库计算、金额校验、报告组件和 CSV 生成器：温哥华入账月份、已结束自然月、期初+正向入账−负向支出=期末。单次查询汇总覆盖所有流水；详情最多1000条、页面前100条；超过1000条仍显示完整汇总但拒绝导出不完整CSV。生成时点不同、后来有入账时，两次查询可能不同，不声称文件自动更新。

旧运营中心月度摘要按北京时间划月（还允许当前月），现标题明确为“北京时间月度资金摘要”；保留原内部口径。核对客户文件时使用新入口。月结工作台中的月份是广告结算月份，点击资金查询后应检查实际入账月份。当前/未来结算月入口不把未结束月份传给资金页，而打开最近已结束月份，并在筛选器和报告标题明确显示月份。

已关联正式账单的资金流水增加公开的 `statement_month`，财务端可去该账单的结算月份与编号位置；不按扣款月份推断广告结算月份。财务链接进入内部制单复核记录，客户链接仍进入自己的已发布账单，不混用入口。

## 权限与隔离

新的 `get_ops_monthly_funds(p_org,p_month)` 要求MFA及该企业的 `finance.read`，与现有财务制单/复核权限一致，管理员也须MFA。客户、投放员工、未关联运营单位、缺MFA的账号不可调用。前端角色检查仅用于入口展示，数据库再检查企业范围。

共同计算函数 `build_monthly_funds_report` 对PUBLIC、anon、authenticated、service_role均撤销调用权限，只能由已检查授权的 SECURITY DEFINER 入口调用。原客户RPC仍只接受个人成员+财务授权；不给财务员工增加客户身份或客户RPC旁路。

只输出客户已有的公开人民币资金字段，不返回内部汇率、CAD采购、银行凭证原件或 source_reference。没有人民币钱包明确显示尚未开户，查询失败显示不可用，不把两种情况混为零余额。导出不记录客户已阅，也不写金额或审计事件。

## 验证

PGlite加载001–034，比较客户与财务查询的完整数据及CSV（统一生成时刻后完全相同）；验证内部共享函数不可直接执行、MFA、客户/投放员工拒绝、运营企业关联撤销后拒绝、未开户与失败区分、读取前后资金/审计数量不变。033的月底夏令时边界、零流水结转、超过1000条完整汇总限制仍通过。页面测试验证跨结算月份链接、报错不导出、非财务角色无法先读取企业或资金。

实际预览仍须用户执行034后等待Preview部署，并用获授权财务账号核对实际月份与客户CSV。测试没有修改真实客户、调用银行或读取真实广告密钥。
