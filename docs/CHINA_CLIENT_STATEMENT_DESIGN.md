# 中国客户月度结算账单：待核实的设计方案

2026-11-15。范围：中国运营公司向境内广告客户出具的结算账单。本文是产品设计评估，不是对税务适用或格式合规的认证。本次访问 gov.cn 被网络代理拒绝，未在线核验最新条文。实施前由中国财务结合合同、纳税人身份和实际服务确认。

## 文件性质

系统生成的是商业结算/对账单，不是通过税务系统开具的发票。PDF、公司标志、盖章或电子签名本身不使文件成为税务发票。发票开具义务、时点、品目、税率和金额须独立判断，不能以“非发票”声明免除开票义务。参考核验入口：国家税务总局 https://www.chinatax.gov.cn/ ，中国政府网 https://www.gov.cn/ 。需核验《中华人民共和国发票管理办法》及其实施细则、《中华人民共和国增值税法》及现行配套规定；如作会计原始凭证使用，另核对《中华人民共和国会计法》《会计基础工作规范》的适用要求。

## 推荐展示（并非所有字段均为普通对账单统一法定必填项）

1. 出单主体：合同中的中国服务方工商登记全称、统一社会信用代码、地址、业务联系电话/邮箱；品牌名称可同时显示，不替代法定全称。不能凭“中国智点未来”运营单位标签推断登记主体。
2. 客户主体：合同客户法定全称、客户编号；企业客户税号根据开票和合同需要显示，避免输出个人敏感资料。
3. 文档信息：月度结算账单（非税务发票）、唯一编号、结算月份、服务起止日期、合同/订单参考、出单日期和明确时区。广告统计时区与出单时区分开标注。
4. 费用表：客户约定的服务项目、计费依据/数量与单价（适用时）、人民币金额、折扣/调整（实际存在时）、合计。约定费用可按广告与执行服务、运营服务、其他已约定费用分列；不得自动公开内部成本、利润或内部公司间分成。
5. 税务口径：明确本账单金额含税或未税，但必须来自核实过的合同与计税配置；无依据时不计算税额、不写税率、不默认免税。发票类型、项目及税额以依法开具的发票为准，不自行把所有费用归为同一税目。
6. 资金状态：此期间结算金额、本期已从预付账户扣除金额、尚需支付金额（有可靠数据时）。本系统现有已发布账单已扣余额，应明确“已扣款，请勿重复支付”；不能将账单总额当作新的应付金额。余额如展示，应说明是结算时余额快照还是当前余额。
7. 发票与联络：独立的发票状态/申请途径、对账咨询入口、已实际关联的发票号码。不可推断“已开票”；申请不等于开具。不为已扣账单增加默认银行汇款指引。
8. 确认区：按合同约定提供对账联系人及必要的签章/确认方式；不默认所有普通对账单必须盖章，也不生成假印章。客户已读不等于同意收费或具有法定电子签名效力。
9. 页脚：出单主体、账单编号、页码；每日展示/点击等投放明细放附件，财务摘要优先。测试账单继续明确虚构验收、不可付款、不可用于税务或正式入账。

## 当前代码差距

`src/lib/billing/statement-export.ts` 使用品牌页眉、一般摘要和每日明细；`clientStatementSchema` 无出单主体、合同引用、税务口径、发票关联或出单主体快照。现有发布时间按温哥华展示。不可从当前报价表或未来公司资料回填并改写历史已发布账单。

## 实施顺序

- 先核实中国公司法定名称、统一社会信用代码、业务地址、对账电话/邮箱，以及合同的含税约定、开票主体和流程。
- 建立经管理员核实的出单主体资料与版本；在新账单发布时保存不可变的主体/客户/合同/税务口径快照。缺少核实资料时不能把导出件描述为对外正式合规账单。
- 新模板第一页以主体、客户、结算摘要、费用表、扣款状态和开票说明为主；每日投放明细置于附件。保留人民币金额精度和权限隔离。
- 已发布历史账单不重算、不覆盖；资料缺失通过有审计记录的补充文件或受控更正流程处理。
- 先用虚构企业生成样张，经中国财务确认后在 Preview 验证。支付网关和税务开票接口不在此次范围。

## 本次 Preview 样张实现

已按用户要求实现精简 HTML/PDF 打印模板：摘要和费用表在前，投放明细在打印附件另起页；出单时间使用北京时间，广告统计保留账户时区。明确验收账单才显示“中国运营公司的法定全称（虚构测试）”及 `TEST-NOT-VALID` 无效代码占位。没有确认普通结算单统一必须列地址、电话、邮箱的依据，本版省略，通过现有客户中心对账；这不等于确认这些信息在所有合同、发票或原始凭证情形下均可省略。法定名称和信用代码作为主体识别字段预留，并不声称两者均为所有商业对账单统一法定必填项。真实账单不套用测试主体，缺少资料时标明主体未核实；不得宣称模板已获税务合规确认。CSV 原导出格式保持不变。真实资料上线仍需主体快照和发布审核设计，不能简单用全局常量覆盖历史文件。
