# 32 月结账单问题跟进

在035之后执行 `supabase/migrations/036_statement_question_workbench.sql`。仅增加只读查询，沿用现有035账单关联和原工单回复/状态功能，不增加收费、审批、退款或月结锁定。

## 日常使用

月结工作台选择企业和广告结算月份，新增“本月账单问题跟进”提示：待处理总数、新建、处理中、服务团队已处理。点击“查看 / 处理本月账单问题”进入 `/zh/operations/statement-questions?company=<UUID>&month=YYYY-MM`；运营中心也提供独立入口，英文路径相应使用 `/en/`。

筛选依据是已关联正式账单的结算月份，不是提问日期、回复日期或钱包扣款月份。十月账单的客户十二月追问，仍计入十月并重新打开原工单。一般服务工单、未关联账单的财务问题不计入此提示，可继续在原服务工单区查看。

列表待处理优先、同一组按更新时间及ID倒序，最多100条；所有汇总按全部匹配工单计算。超出100条明确提示，历史工单仍能通过原链接在同一企业/月范围内直接查详情，不先从截断列表中查找。选择工单、发送回复或刷新继续保留企业、月份，重新筛选则清除当前工单选择。

原五项主流程继续保留；本提示单独显示客户反馈，不把客户已读与工单处理合并。不设第六个审批节点，不因有待处理工单自动撤销或锁定原账单。没有待处理问题也不代表客户同意收费或整个业务结清；服务团队“已处理”仍可因客户继续回复而重开。

## 查询与权限

RPC `get_statement_question_workbench(p_org,p_month)` 要求MFA及对应企业 `finance.read`。客户、投放执行、非财务客服不能通过新接口读取其他人的问题。只返回企业/月、状态计数、100条基本标题与关联账单元数据，不返回正文、作者身份、请求键、输入摘要、汇率或内部采购数据。正文只在选择明确工单后通过原RLS查询。

页面与数据库都校验企业/月范围；详情查询还同时限制工单ID、企业、关联账单月份、billing类别及非空账单关联。原工单RLS与回复API不变。查询失败、范围不符或计数校验失败显示“状态暂不可用”，不冒充零条待处理。即使问题查询失败，原月结来源、账单与资金状态仍可查看。

## 验证

隔离PGlite贯穿测试扩展至001–036：财务标记已处理后计数改变、客户追问重新计入待处理、月份与企业隔离、客户/投放角色/缺MFA拒绝；添加105条明确虚构已处理记录后，106条完整汇总与100条列表保持一致，原待处理工单仍列在前面。查询不新增资金流水。测试没有修改真实客户数据。

页面测试检查范围在SQL查询中限制、打开工单保持企业/月、错误不推断零条、返回其他工单ID不显示回复表单；原客户提问、财务回复和月结页面回归保留。

预览验收：执行036并等待Preview部署后，财务从“月结工作台”选择实际有正式账单的企业/月。没有关联问题时应显示未发现，不能为让流程有数据而制造虚假客户争议。实际客户提问与回复后刷新即可看到状态变化。
