# 管理员汇率与跨境成本试算（017）

## 权限迁移

独立测试库整份运行 `supabase/migrations/017_private_fx.sql` 一次，建议保存“13 管理员汇率权限与客户结算校验—已执行”。不重跑初始化。迁移不更改已有汇率数值、历史报告或余额，收紧既有 billing_fx_quotes 的 RLS：仅 active admin 且完成 MFA 可 SELECT。客户和普通财务不能直接读取，生成含汇率的内部结算草稿也改为仅管理员；独立财务复核仍查看结算结果并审核，不要求其声明核对未获授权的原始汇率。

客户报告查询不请求汇率关系，浏览器不接收内部汇率。只读函数 validate_client_statement 检查客户自身财务权限、已发布状态、来源金额、行合计和锁定报价，返回布尔值；其他企业或未知报告返回false。不提供公开验算接口。数据库未更新时客户报告校验失败关闭，不能将不可用记录当作可发布。

这是字段和访问权限保护，并非数学上防止反推：同时获知CAD原币和CNY结算金额的人仍可能计算有效换算比例。不能承诺“任何人都无法推算汇率”。迁移不能撤回过去已经下载的数据。客户按原币成本结算的约定应提供其有权核对的依据，不能把内部加价说成官方汇率。

## 汇率来源

试算仅管理员可见，支持手动试算和加拿大央行最近公布参考汇率。固定服务器URL：
`https://www.bankofcanada.ca/valet/observations/FXCNYCAD/json?recent=1`。

FXCNYCAD 为每CNY对应CAD，使用精确整数运算倒数换算为每CAD对应CNY，HALF_UP保留8位小数，保留原日期、原值和获取时间。非可成交银行报价，节假日不伪装为当天新报价。缺失、未来或超过7天的数据拒绝；超时、非成功响应、超64KiB响应或无效格式返回不可用，不默默复用旧值。

开发环境到央行域名的真实请求被网络策略403阻止，只有固定样本与模拟接口测试通过；不能宣称实时连接已验证。需在部署的Preview以管理员身份实际获取验证。未修改Codex网络设置或发布环境配置。无法获取时可主动选择手动试算，不能自动回退伪造官方来源。

## 跨境成本

本轮仍是浏览器内试算，不保存汇率／跨境报价、不锁定正式结算、不产生应收应付、不扣钱包或执行汇款。现有收费规则保存接口仍只保存服务费草稿，不会保存该试算的汇率和跨境成本。

成本基数为按所用汇率折算的上游采购总额，不包含中国运营服务费。四种方式：不另计、固定CNY金额、按成本比例加成、从汇出总额扣费时倒推所需总额（向上取整到分，确保覆盖所需净额）。

30160元加成20%时成本6032、合计36192；若服务商扣汇出总额20%，需要汇出37700、费用7540。两者不能混用。倒推比例必须小于100%。

分别显示公司承担和拟向客户报价金额；默认公司承担，不增加客户试算额。向客户单列报价仍须客户确认，不是已生效收费。若勾选汇率已含服务商汇差／费用，必须选择不另计，防止重复计算。使用已含费用的报价时不再用本页重复增加同一费用。

宽屏左列中国CNY、右列加拿大CAD；小屏上下排列。原始平台广告费不加价，代理服务费和跨境成本分别列示。汇率说明只在管理员试算结果显示。服务收入不等于净利润，承担费用的法律主体及真实付款凭证还需正式公司间结算流程确认。

## 后续

完成实际来源连通验证，再开发按公司／客户保存不可变的汇率与成本报价快照、证据与审批、报价有效期和实际付款差异处理。自动参考值不直接成为客户收费指令。正式客户收费及公司间结算仍需明确约定和双人复核，不因打开参考接口而自动执行。

## 汇率入口澄清

界面统一为三种选择：央行参考汇率＋跨境成本单列、手动综合汇率（已含汇差／相关费用）、手动基础汇率＋跨境成本单列。移除容易混淆的独立“已包含／未包含”下拉框。

综合汇率模式停用另计成本字段，计算时强制 none、零另计费用和 includedInRate=true；即使切换前填写过20%也不会重复叠加。保存时沿用 manual 来源和明确的 includedInRate 标志，不改变既有数据库格式或历史报价。基础汇率及央行模式则 includedInRate=false，按单独配置计算额外成本。

综合汇率的嵌入费用不能仅由一个数值还原，界面及历史报价应显示“已包含，未另列”，不能把额外计费为零解释为真实跨境成本为零。两家公司的服务费仍按独立规则计算；综合汇率不自动包含代理服务费。

含费综合汇率下，平台CAD广告金额折算出的CNY金额也含嵌入费用；若中国服务费选择该折算金额作为比例基数，其基数亦含这部分费用。正式约定需明确这一点。若要剔除嵌入费用，必须另有基础汇率或费用明细，系统不能凭综合汇率猜测拆分。
