# 收款入账验收

## 第一步：托管数据库自动回滚测试

文件 `supabase/tests/bank-receipt-acceptance.sql`，只在隔离 Supabase 测试项目 SQL Editor 整份执行，不是 migration，不替换末尾 rollback。保留编号冲突时停止，不覆盖已有用户。

覆盖：虚构收款账户和人民币钱包、制单不增加余额、兼任制单复核仍不得自审、银行流水大小写和空格归一化防重、客户不能审核、未完成 MFA 的模拟会话不能审核、独立复核、重复审批只入账一次、冲突重试拒绝、客户不能读取内部银行依据。金额100001分，预期精确为1000.01元。

结果中 receipt_acceptance 应为 PASS，最终 fixture_users 和 fixture_companies 均为0；所有虚构员工、客户、收款账户、流水和审计均回滚。不会给已存在的两个测试客户增加余额，也不创建可登录员工。没有连接真实银行、付款、短信或广告账户。

这是模拟 Auth claims 的真实 authenticated 数据库角色测试，不证明浏览器登录、实际 MFA 或并发网络请求已完成。出现错误保留错误信息，不拆开运行，不改为 commit。

## 第二步：真实会话验收（待配置）

由所有者创建两个独立员工 Auth 账号（密码与 MFA 仅本人管理），将其 UID 分别登记为中国财务制单、财务复核；不复用客户账号，不把普通员工升级为 admin。角色分配在管理员界面完成。不要在聊天或仓库提供密码、TOTP种子或服务密钥。

在 Preview 使用不同浏览器分别登录两位员工，访问 `/zh/operations/collections`。所有者先核实并配置测试专用、明确不可付款的虚构收款指引；不要把虚构收款指引用于正式客户钱包。浏览器测试需使用新的专用虚构企业，避免把模拟金额混入当前测试客户的余额。测试数据将持久保留，不能用已入账流水删除来清理。

制单方登记虚构银行依据并保存；客户余额保持不变。独立复核方确认后，客户应只增加一次正确金额；重复操作不再次入账。同人审核、未授权人员、金额不匹配及停用收款账户的审核均应被拒绝。

两位员工和专用测试钱包尚未完成真实会话验收时，不宣称收款功能已可处理正式资金。
