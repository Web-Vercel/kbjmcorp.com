# Customer statement selection

Owner approved replacing stacked complete monthly bills with month selection and one bill at a time. Default selects the newest published settlement month in the authorized result set, then the most recently published bill. Available months come from the latest 100 published records in the selected wallet scope; the page labels this limit rather than implying complete lifetime history. Same-month multiple bills get an additional ad-account/bill selector. Wallet changes restart selection; month changes discard the previous statement ID.

Existing server-side wallet/month/statement RPC filtering remains authoritative. Filtered views retrieve an additional authorized catalog for selector options. Direct links retain their original ID and access-error behavior, including bills outside the recent catalog; selected data is merged into choices without replacing the linked bill. Invalid/failed data never renders downloads or zero-charge claims. Downloads, questions and read acknowledgements remain attached to the single displayed statement. No SQL, permissions, data or financial workflow changes. After Preview review, the owner explicitly approved synchronizing this isolated presentation change to Production.

Validation: 23 focused tests covering selection navigation, latest-month display, direct links, access failures, reading acknowledgement, questions and manual data presentation; production build including TypeScript. Hosted authenticated appearance remains for owner review after Preview deployment Ready.
