# 公司间采购对账（已发布账单口径）

入口：`/zh/operations/upstream`。仅管理员及 MFA 会话可用；财务制单、财务复核、加拿大投放员工和客户均不能调用查询。现有 001–027 已执行的项目，SQL Editor 新建「24 公司间采购对账」，执行 `supabase/migrations/028_upstream_reconciliation.sql`。该迁移仅新增只读受控函数，不创建任何资金、应付、付款或账单记录。现有项目不得运行完整 bootstrap。

按自然月及可选客户企业，从已发布的 `monthly_client_statements` 关联不可变制单和报价版本。未发布报价、待复核/已退回的制单排除。已发布账单不会因报价归档或来源交接暂停而从历史采购对账中消失。

金额来源：平台广告成本 CAD、加拿大执行服务费 CAD、二者之和采购结算额 CAD；锁定报价折算的采购 CNY、中国服务费 CNY、客户单列跨境成本 CNY、另列公司承担跨境成本试算 CNY、客户账单实际已扣合计 CNY。查询校验 CAD 拆分和 CNY 账单对应关系；异常金额直接失败，不省略记录或将其当零。总计按所有匹配行计算，再限明细为最近 200 条；范围超限时提示缩小企业范围，禁止导出不完整 CSV。

CAD 与 CNY 分列，不能相加；服务费不是净利润，报价跨境成本不是实际银行手续费，综合汇率包含的费用无法单独拆分。此表是账单口径的采购核对资料，不是会计应付确认或汇款证明。

接口明确返回 `payment_status: not_tracked`。公司间付款流程尚未接入，不能将客户已扣款推断成中国已付款或加拿大已收款，也不应把缺少系统付款记录判为未付。实际付款登记、部分支付、凭证独立复核和差额处理属于后续阶段；不能通过重复扣客户钱包代替公司间结算。

每行保留正式账单编号、锁定报价编号/版本和发布时间，可进入对应企业月份的原结算及发布回执。仅提供明确发起的本地 CSV 下载，不自动对外发送。文件包含内部成本，仅供授权管理人员保管；字段白名单不输出完整报价、汇率参数、原始 API 响应、银行凭证或客户授权信息。

验证包括 PostgreSQL 多账户汇总、未发布草稿排除、企业隔离、管理员 MFA、角色拒绝、报价归档/来源暂停后历史保留，以及重复查询不改变钱包；页面故障不显示零、CSV 注入防护和截断导出阻止。没有对真实银行、客户账单或余额进行测试性写入。

后续 029 已新增独立的 CAD 到账核对流程，见 [UPSTREAM_PAYMENT_VERIFICATION.md](UPSTREAM_PAYMENT_VERIFICATION.md)。028 报表仍只展示采购账单口径，其 `payment_status: not_tracked` 指此报表不汇总付款状态；付款分配和核销必须到独立页面查询，不能从采购 CSV 推断。
