# 企业 CRM 与客户门户

## 缺口与本次范围

原后台已有咨询、咨询转公司、项目及成员权限，缺少人工企业建档、完整联系人、手机号首次关联、财务授权界面及合同记录。本次补齐单机构的内部 CRM 和外部客户门户连接：智点未来的授权员工管理多家广告客户公司，客户只访问自己的公司。不是供多家互不相关代理机构共同使用的多租户商业 SaaS；没有 SaaS 订阅、计费、独立机构管理员或租户分区功能。

工作链：人工新建企业或咨询转公司 → 完善法定资料和联系人 → 核实授权/准备合同 → 管理员批准手机号邀请及业务/财务范围 → 客户手机号验证并登录 → 领取预先批准的公司权限 → 查看自己的公司、资金、报告及获开放合同。

本轮均使用虚构数据；迁移 010 只在 PGlite 执行，没有部署托管数据库，没有发送短信、邀请消息、合同、付款或退款。

## 公司及联系人

- 人工建立企业，无需从网站提交咨询；支持显示名称、法定名称、国家/地区、注册编号、行业、HTTPS 网站、客户阶段和内部备注。
- 咨询转成的已有公司可直接进入 CRM 补齐，不重新建立第二家公司。
- 档案更新用 revision 检查防止覆盖其他人的新资料。
- 业务、财务、法务/签约联系人分别登记，可录入国际电话/邮箱。手机号登录邀请当前仅支持 +86 手机号码。
- 联系人不是登录用户。录入联系人、标注为“财务联系人”、修改手机号，都不自动授予或转移客户权限。
- 归档公司会撤销未领取邀请；现有成员访问和历史财务资料需管理员另行核实/撤销，不将业务阶段直接等同于财务账户注销。
- 列表最多最近 100 家，联系人/邀请/合同各最多最近 100 条；大量数据的分页、批量导入、销售任务、跟进日历和高级检索未实现。

## 当前权限

| 身份 | 公司与联系人 | 登录/财务授权 | 资金信息 | 合同 |
| --- | --- | --- | --- | --- |
| 内部管理员 + MFA | 管理本机构全部客户 | 批准/撤销/调整 | 读取公司余额与待核对数量，开立空 CNY 钱包 | 起草、登记发送/签署、控制客户可见 |
| 内部业务人员 + MFA | 维护本机构客户档案/联系人 | 不可 | 不可读取财务汇总 | 不可读取/管理合同价格 |
| 客户业务成员 | 安全的本公司基本资料与原有项目权限 | 不可自授权 | 无财务授权则不可 | 无财务授权则不可 |
| 客户财务 viewer | 本公司基本资料 | 不可自授权 | 余额、账单、月报只读 | 管理员明确开放的非草稿合同 |
| 客户财务 manager | 同上 | 不可自授权 | 同上，并可登记充值核对申请 | 同上 |

业务协作角色不等于内部管理员，也不自动获得财务权限。内部人员当前是本机构范围的角色权限，没有新增“销售人员仅限自己负责的客户”的记录分配功能。内部员工初次账号开通/停用仍通过受控管理渠道，未提供公开员工注册、自授管理员或完整员工管理界面。

开立 CNY 钱包只建立一个已知为零的空账户，重复请求不会创建第二个钱包或重复记录开户事件；不产生收入、充值、广告扣款或退款。真实到账核对、财务过账/复核和支付渠道仍未接入。

## 手机邀请与首次登录

1. 管理员在已完善、未归档的客户档案中选择有姓名和 +86 手机号的联系人。
2. 选择业务只读/协作，及独立的财务 none/viewer/manager；填写公司授权核实参考，并明确确认。
3. 数据库生成 7 天有效授权记录，不创建 Auth 用户，不发送任何短信或邀请消息。
4. 客户走既有手机号验证码登录。客户中心挂载后通过同源 POST 请求领取授权，服务端核实当前登录身份；数据库只使用 auth.uid() 对应 Auth 中已确认、未删除、未被封禁的手机号，不使用浏览器提交的手机号/公司/角色。
5. 只有明确批准、未过期、未撤销、联系人号码仍匹配、公司未归档且创建管理员仍有效的邀请可被领取。手机号在 Auth 中存在歧义时不自动授予。内部员工身份不能以此领取客户权限。
6. 领取后建立公司成员及独立财务权限，重复领取不重复授权。已有有效手机号登录会话可以领取新授权，不会每次自动再发送短信。
7. 只有成功领取新权限才刷新客户中心；错误显示可重试，不伪造登录或公司关联成功。

撤销成员/调整财务权限时，数据库会使相关旧的待领取邀请失效，避免旧邀请恢复被撤销的权限。联系人手机号变更使未领取邀请失效，但不会将已关联的 Auth 账号转给新手机号；管理员需单独审查旧账号。

手机号证明号码控制权，企业授权仍需人工核实。号码回收、SIM 接管、账号恢复与手机号变更的受控流程沿用 PHONE_AUTH.md 中尚未完成的边界；不能把手机号验证宣传为企业身份认证或完整 KYC。

## 合同模板与记录

- 提供中文广告代理服务协议示范草稿，包含主体授权、服务范围、广告费与代理费分列、人民币结算依据、中文报告、资料保护、退款/终止和外部签署记录等基础结构。
- 服务方真实法定名称由管理员填写，系统不猜测品牌对应的注册法人。客户法定名称从其已完善档案复制，形成快照；后续档案改名不覆盖历史合同。
- 模板正文、服务范围、定价、退款条款、期间与主体都保存在合同记录中；不是每次从当前模板重算旧合同。
- 初始状态为 draft 且客户不可见。管理员可人工登记 sent → signed/expired/terminated 等状态；不能从已发出/签署状态退回草稿绕过内容锁。
- 发出后的主体和条款不能覆盖。已登记签署后签署日期/参考号不可改写。修改条款需起草新记录，本轮未提供完整修订关联/补充协议流程。
- “已登记发送”不发送邮件或消息；“已登记签署”要求外部文件参考号和实际签署日，但不执行电子签名、不验证文件真实性、不能证明签署人身份或法律有效性。
- 客户只能读取管理员明确开放的非草稿合同，且必须有同公司财务权限。客户不能看到内部备注、未开放草稿或合同创建人的 Auth UUID。
- 可浏览器打印/保存 PDF，草稿/演示都有标识，打印时每页保留 DRAFT 标记。登记副本不能替代真实签署原件。
- 模板中的主体地址、授权代表、适用法律/争议处理、具体交付和数据处理等仍须按真实业务完善；示范模板不等于已经审阅适用于该客户的标准正式合同。

尚未实现私有合同附件上传/下载、文档哈希验证、签署供应商、签署文件保管、自动续约提醒、合同法律审阅、付款或退款执行、数据保留/删除及恢复流程。原件存放地区仍按用户决定暂不选择；当前不收集真实文件。

## 路由

| 路径 | 用途 |
| --- | --- |
| `/{locale}/admin/crm` | 人工企业建档与列表 |
| `/{locale}/admin/crm/{id}` | 档案、联系人、邀请、成员权限、财务汇总及合同 |
| `/{locale}/admin/crm/contracts/{id}` | 合同登记、客户可见范围及打印 |
| `POST /api/admin/crm` | 角色受控、同源、有限 JSON 的 CRM 操作 |
| `POST /api/client/claim` | 从已验证身份领取预先批准的邀请，不接受客户指定目标权限 |
| `/{locale}/account/company` | 客户自己的基本资料与获开放合同 |
| `/{locale}/account/contracts/{id}` | 同公司财务权限约束的合同副本，无权限与不存在统一 404 |
| `/{locale}/crm-preview` | 页面内存的虚构 CRM 操作演示 |
| `/{locale}/crm-preview/contract` | 虚构合同草稿和 PDF 示例 |

员工演示侧栏新增“企业客户 CRM 演示”。真实客户中心提供“企业资料与合同”入口。公开演示不创建真实登录，不领取真实邀请，不发送业务写请求，刷新即清空。

## 验证与真实服务边界

SQL 本地验证覆盖手工新建、联系人不授予权限、MFA 和角色限制、OTP 已验证身份领取、跨公司隔离、重复领取、失效/过期/归档邀请、旧邀请不恢复撤销权限、独立财务授权、合同草稿不可见、条款/签署记录不可覆盖、签署证据要求及最小审计载荷。

自动化和浏览器演示不等于真实 GoTrue/SMS、托管持久化、实际合同文件或生产认证已联调。部署地区、现有本地 Supabase 镜像访问阻塞、真实平台连接和财务过账等限制仍见 PHASE2_READINESS.md。只有在这些服务就绪后，才能用独立测试身份实际验证“后台授权 → 手机 OTP → 客户看到本公司资料”的全链路。

本轮验证结果：201 项自动化测试（25 个文件）、Next.js 生产构建与 TypeScript 检查通过；38 项 CRM/邀请/客户隔离/合同预览检查、28 项员工后台回归与 25 项资金/月报回归通过。浏览器覆盖 320、375、768、1440 宽度，无页面外溢或未捕获错误；公开 CRM 演示没有业务写请求。两页中文合同草稿 PDF 已实际生成，并核对虚构声明、非签署文件说明、费用条款及 DRAFT 标记。
