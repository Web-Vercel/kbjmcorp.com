# 31 账单问题关联与财务回复

在034之后执行 `supabase/migrations/035_statement_service_questions.sql`。复用现有服务工单及回复，不增加金额修改、退款、扣款、客户收费同意或自动客户已阅确认。

## 正常流程

1. 获授权客户在 `/zh/account/statements` 的正式账单下展开“对此账单有疑问？”，输入标题和问题。编号、企业、类别billing及结算月份由数据库按真实已发布账单填写，不接受浏览器指定客户身份、金额或状态。
2. 提交成功后打开工单，或随时点击“查看本账单相关工单与回复”。`/account/service?statement=<UUID>` 在数据库查询条数限制前筛选对应账单；选择工单继续保留账单范围，并能返回原账单。此范围不显示无关联的一般建单表单，新的账单问题从原账单提交。
3. 授权财务在三方运营中心原有“服务工单”处理区查看、回复并更新open/in_progress/resolved状态。关联账单的月份和编号保留，财务链接进入内部结算记录；客户链接只进入客户自己的正式账单。
4. 客户在同一工单查看回复、继续追问。现有规则使已处理工单在客户继续回复后重新打开。处理状态由服务团队维护，不声称是客户确认或已解决收费争议。

界面现提供中英文。此版本不发送邮件、短信或其他外部通知；双方通过既有服务工单入口查看。提交、回复或状态变更不会修改原始账单和余额；真正金额更正仍需独立的正式财务流程。

## 授权与持久化

原表新增公开可读的 `statement_id`、`statement_month`，以及不对客户SELECT开放的请求键和输入摘要。原RLS继续决定账单工单可见性：客户必须属于企业且有财务授权；内部仅MFA财务/管理员可以看billing工单，加拿大投放及一般客服不能因此读取财务问题。撤销客户财务权限后，也不能查看、回复或用相同请求键取回原工单。

数据库触发器核实账单所属企业和月份，创建后不允许改关联；所有原无关联工单仍兼容。新RPC拒绝内部员工代替客户创建账单问题。正文只在工单消息表保存，审计只记录企业、类别和账单编号，不复制问题正文或内部成本。

同一登录用户在同一账单上，使用相同请求键和相同内容重试只返回原工单，不增加消息或审计。请求键换内容会被拒绝。同一企业创建过程加锁，与原有20条待处理工单限制配合；即使已达到上限，原请求重试仍能取回原记录。通用工单及现有回复数量限制仍保持。

前端同一页面提交保留请求键，30秒超时后显示“结果未知”，保留内容并提示先查已有工单；原内容重试使用同一键，编辑内容则换键。完全重新打开页面会重新生成请求键，因此用户应先查相关工单，不能将新页面的手动重复建单承诺为全局内容去重。

## 验证与验收

隔离PGlite贯穿测试加载001–035，验证客户提问→同键重试→财务回复→客户追问重开→撤销权限，关联原账单不可篡改、跨企业及投放角色隔离、上限后仍可重试、原一般工单仍可创建/回复。原案例客户最终资金仍CNY395、总共三笔资金流水，公司间核销仍CAD110，没有因工单新增费用。测试只使用虚构资料。

API测试覆盖同源、登录、输入限制、忽略伪造金额/企业、错误脱敏。组件测试覆盖无自动提交、服务端成功才显示已提交、30秒未知结果、相同内容重用请求键。页面测试覆盖数据库先按账单筛选、客户/财务不同链接和处理状态说明。

真实预览：执行035并等待Preview部署后，由真实获授权客户从已发布账单提交实际问题，财务在既有工单区回复。没有实际问题时不必制造虚假争议来填充流程状态。
