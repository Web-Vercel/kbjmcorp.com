# 客户余额、扣款流水与正式账单衔接

已有001–031的项目，SQL Editor 新建「28 客户余额与账单对账查询」，执行 `supabase/migrations/032_client_statement_navigation.sql`。仅新增受控只读汇总及筛选查询、扩展原账单查询的公开账户标识；不增加审批、收费、到账、钱包流水或查阅确认，不变更原权限。现有项目不要运行完整 bootstrap。

## 客户中心

首页现在读取正式月结账单的最近结算月汇总，而不只读取早期 `monthly_ad_reports`。数据库按获授权的钱包选择最近账单月份，再汇总该月所有已发布账单，不受前端最近100条记录限制。同月多个广告账户不会只显示其中一个。

公开分类与月度账单一致：广告与执行服务、运营及约定其他费用、已扣总额；不将采购换算部分误写成纯平台原始广告费。CNY汇总不暴露CAD原始成本、汇率或利润。历史格式月报独立收起保留；新旧记录不叠加重复计算。新汇总失败时显示未知，但已有余额、已入账流水仍可读取。历史账户币种不自动换算。

只有符合 `monthly-statement:<UUID>` 规则的负数广告/服务费扣款才生成账单链接。服务端移除原始 `source_reference`，不把内部银行参考或其他来源标识发给客户端。两条费用扣款可以指向同一份正式账单，不表示收取两次账单。

## 账单定位及返回

客户可按获授权账户、结算月份筛选。钱包、月份、指定账单编号均在数据库取最近100条之前筛选；流水指向的历史账单不会仅因较旧而无法定位。明示列表最多100份，最近月汇总则覆盖该月完整数据，不把部分列表冒充全月总额。

账单详情可返回相同账户的余额和最近流水，返回参数按钱包UUID定位，不按公司显示名称匹配。不同公司的名称相同时，也不会因名称相同而串联数据。未经授权的账户不会显示；内部员工的广泛运营RLS权限也不绕过客户财务授权。

结算月份是广告使用期间，实际扣款时间是发布记账时间，两者可不同。银行充值日期、账单月份和公司间付款日期亦不同；本轮不把这些时间混成一条“本月银行收支”。

## 验证

隔离贯穿案例继续核对CNY1,000入账、CNY605扣款及余额CNY395；正式首页汇总与账单一致，CAD核销不改变客户余额。额外两个虚构广告账户验证同月费用完整汇总和旧账单精确定位。前端/加载器测试覆盖无旧月报仍显示新账单、汇总故障不显示零、流水原始参考剔除、仅合法费用来源可链接、同名企业按钱包ID返回及原演示兼容。没有修改真实客户、银行或广告账户数据。
