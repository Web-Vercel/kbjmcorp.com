# 两个测试企业：真实会话合同访问验收

仅在已初始化的独立测试数据库执行。不要在正式客户数据库执行，脚本不会自行判断 Supabase 项目的部署用途。

前提：测试企业A和测试企业B名称各唯一；各有一个已授权的非员工只读客户；恰好一个 active admin。脚本不会创建用户或授权。存在重复名称、管理员不唯一或保留编号碰撞即整体停止。

1. SQL Editor 整份运行 `supabase/tests/preview-contract-fixtures.sql` 一次。保存为“08 虚构合同访问验收—已执行”。结果应为两条虚构合同链接。
2. 在 Preview 最新版本分别登录 A / B（不同浏览器）。进入企业资料与合同，确认只看到自己公司的合同。
3. A 自己的合同路径：`/zh/account/contracts/e5800000-0000-4000-8000-000000000601`。B 自己的路径：`/zh/account/contracts/e5800000-0000-4000-8000-000000000602`。
4. 分别打开自己的链接，应成功；交换链接，应返回 404，不能出现另一企业的名称、条款。刷新后再次确认。
5. 打印预览应保留虚构合同提示。退出登录后访问详情不能读取合同。
6. 验收结束整份运行 `supabase/tests/cleanup-preview-contract-fixtures.sql`。它只将保留编号且仍符合测试标记、未签署状态的合同终止并隐藏，保留不可变条款及审计历史，不删除合同、账号、企业或授权。修改过的测试合同会阻止自动清理，需人工核对。

测试合同状态 sent 仅为了覆盖客户可见规则；不是实际发送或真实签署。内容及打印水印明确为虚构数据。脚本没有短信、广告平台、银行、钱包流水和真实支付操作。created_by 是测试管理员登记标识，审计 source 为 owner_sql_editor、actor_id 留空，避免伪造网页登录操作。

月报尚不通过本脚本发布。正式月报需要来源文件、核对原始金额及汇率、审核与发布记录；不得为了造测试数据而跳过这些校验。现有自动回滚 SQL 已覆盖数据库层月报隔离，实际报告详情浏览器验收仍未完成。
