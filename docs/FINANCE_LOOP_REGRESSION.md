# 财务闭环回归验收

运行 `npm run test:finance-loop`。本命令将既有数据库边界、银行到账、主流程贯穿、付款通知API/表单与资金页面的核心测试集中运行。当前10个文件、123项全部通过；类型检查通过。这是选定闭环测试集合，不代表全仓库所有测试或真实业务人工验收已经完成。

全部测试使用本地PGlite空库、虚构企业/客户/银行依据，或模拟认证/网络响应。不读取真实广告密钥，不发送短信，不登记真实银行到账，不向Preview数据库写数据。

| 环节 | 保护条件 |
| --- | --- |
| 客户付款通知 | 通知须有有效ID回执，未知结果保留输入，通知本身不创建余额 |
| 银行到账 | 已核实实际到账并由另一人复核后入账；重复复核不重复入账，最终保存失败回滚 |
| 企业与角色权限 | 跨企业隔离；员工二次验证；客户仅获授权财务资料，不能读内部汇率 |
| 月结来源、报价及扣费 | 来源、报价和月份一致；独立复核；正式发布才扣款，重复发布受保护 |
| 客户查看与导出 | 财务授权独立检查；原币数据、客户结算和资金流水口径保持分开 |
| 公司间核销与撤销 | CAD核销不再次扣客户余额；复核和撤销保留来源与记录 |

## 修复的6项旧失败

1. 旧测试假设客户可读取锁定汇率，改为客户不可见、管理员缺少二次验证不可见、管理员完成二次验证可见；原已发布客户账单金额仍可读。
2. 含私有汇率的旧prepare_ops_reconciliation接口按017要求仅管理员调用。测试明确拒绝加拿大、制单、复核、未分配角色和未完成二次验证的管理员；只有合法管理员继续测试当前有效报价及独立复核。
3. 因上述错误角色导致未产生草稿的后续复核用例恢复执行，仍检查不扣余额、不发布客户报告。
4. 过期草稿用例用合法管理员建立原草稿后，仍检查新来源使原版本失效，拒绝旧版本复核。
5. 非CAD来源用例先使用有权调用适配器的管理员，再验证币种拒绝，避免被更前面的身份检查遮挡。
6. 银行自审用例先验证缺少复核角色被拒绝，再在隔离库显式授予双角色，验证仍禁止本人复核，并在finally恢复角色。消除对前面另一个测试的角色副作用依赖。

未删除或跳过用例，原72项全部保留；新增权限分支与过期报价断言。没有更改supabase脚本、生产接口、实际账号权限或数据库结构。当前月结制单与独立复核仍是原流程，不因调整旧适配器测试而改成仅管理员制单。

本轮仅测试、验收文档与快捷命令变更，不增加页面、审批步骤或SQL脚本。真实客户的银行原件、收费约定、整月来源及客户登录仍须按既有人工验收办理。

到账制单与复核专用回执已纳入同一命令，见 [BANK_RECEIPT_SUBMISSION_FEEDBACK.md](BANK_RECEIPT_SUBMISSION_FEEDBACK.md)。记录ID和决定须匹配，未知结果不清空输入，原虚构企业隔离也有回归覆盖。
