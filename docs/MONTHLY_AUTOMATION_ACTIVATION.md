# Preview unattended monthly draft preparation

## Implemented

Migration 056 adds explicit per-binding settings and durable jobs unique by binding/month. An AAL2 administrator records the applicable percentage-fee/customer-borne-transfer agreement and opts in. No setting is enabled by the migration. The server worker claims one job for the configured advertiser account, fetches its closed natural-month report, obtains historical month-end Bank of Canada FX, computes the existing fee rules, and atomically stores the raw source, handoff, immutable quote, settlement draft, job receipt and audit record. No review, publication, customer debit, bank transfer or invoice download is performed.

The worker is an explicit service_role RPC path: it does not manufacture an administrator JWT, save a user's credentials or reuse an interactive session. The server's privileged connection remains a sensitive server secret; RPC execute grants are not a claim that the Supabase service key itself is restricted to these functions. Draft prepared_by and source/quote created_by identify the administrator who authorized the setting. Audit changes explicitly identify background_worker execution and that authorizing administrator. That same administrator cannot independently review their own authorized draft under the existing review rule.

Leases last five minutes and use opaque tokens; stale tokens cannot complete or reschedule a newer attempt. Failures back off, stop after five attempts and remain visible. Pausing/changing a setting cancels outstanding work and invalidates leases. Prepared history is retained. The completion transaction rolls back on incomplete source coverage or scope/calculation mismatch; resolve_ads_month is reused. Existing drafts/publications block further preparation. Unknown completion responses return unconfirmed; a committed job remains prepared and cannot be claimed again. Existing customer and finance projections are unchanged.

Initial support is the currently configured ADS_REPORTING_ACCOUNT_ID/API key only. Other bindings are not read with that key. A paused/removed authorizing administrator prevents claims/completion. No backlog is automatically created: each tick enqueues the immediately preceding month in the advertiser timezone, then services due retries. A completed pending-review draft is not refreshed silently; later upstream changes require a separately reviewed adjustment/version workflow.

## Hosted activation — not executed by this change

1. Confirm the selected Supabase project is **智点未来-Preview**, with 055 already installed. Install **056_monthly_automation_jobs.sql once**, suggested SQL Editor name **54 自动月结任务与授权（脚本056）**. Do not rerun 055 or the new-project bootstrap. Read-only presence check: `select to_regclass('public.monthly_automation_jobs');`.
2. In Preview's server environment only, configure SUPABASE_URL and SUPABASE_SECRET_KEY (or existing legacy server service key), existing ADS_REPORTING_* credentials, CRON_SECRET (at least 32 random characters), MONTHLY_AUTOMATION_ENABLED=true. VERCEL_ENV must be preview. No client-visible variable or browser storage may contain these secrets. Redeploy Preview. The route remains disabled in Production even if copied there accidentally.
3. In 月结办理 → the intended account → 定时月结设置与任务, record the verified agreement and opt in. This authorizes monthly percentage rates, historical BoC FX and separately agreed customer-borne cross-border costs; exceptional fixed-fee or agency-borne agreements must remain manual.
4. From a trusted server invoke GET /api/internal/monthly-automation using Authorization: Bearer CRON_SECRET (plus Vercel protection-bypass header if deployment protection is enabled). Verify one prepared job, exact rates/source/FX, independent reviewer access, no statement/debit and safe repeated invocation. This authenticates to the application, not to Vercel; deployment protection is a separate layer.
5. Vercel built-in crons do **not** run on Preview deployments. Optional daily Preview scheduling is supplied as `supabase/operations/schedule_preview_monthly_automation.sql`, using hosted Supabase pg_cron + pg_net and Vault. Enable these extensions, store the URL and secrets in Vault UI, review the concrete SQL and install it. It deliberately avoids replacing a same-name job. Schedule: 16:00 UTC daily, after the previous month has closed in Vancouver/Toronto. Verify cron job execution AND net._http_response HTTP results; enqueue success alone is not application success. A failed job retries at the next scheduler tick once its backoff expires; daily scheduling therefore means retries can be a day apart. One configured account/job per invocation in this first stage.
6. Pause by disabling the setting, setting MONTHLY_AUTOMATION_ENABLED=false, or unscheduling the named Preview cron. Existing source/quotes/drafts remain stored. Do not enable Production until authenticated Preview acceptance is complete.

The hosted database migration, server secrets, extensions, scheduler and real API/FX calls have not been installed or verified by this development task. No credentials should be sent in chat.

## Validation

Local PostgreSQL tests cover opt-in, role grants, duplicate claims, stale leases, atomic source/quote/draft writes, source mismatch rollback, retry delay/exhaustion and pause/history retention. Worker/API tests cover fixed account scope, closed-month reads, fee calculations, missing FX, lost acknowledgements, scheduler authentication and Production/feature gates. Existing monthly draft and month-close page tests remain relevant. TypeScript, Next.js build and bootstrap consistency are checked separately from hosted acceptance.
